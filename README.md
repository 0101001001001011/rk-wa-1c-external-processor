# Внешняя обработка 1С для платформы RK WhatsApp

Внешняя обработка для 1С:Предприятие 8.3, которая работает с API версии 2
платформы RK WhatsApp: подключает номера, показывает код для входа в
WhatsApp, отправляет сообщения и файлы, читает переписку и контакты.

Обработка не требует изменений конфигурации: это отдельный `.epf`,
который открывается через «Файл → Открыть».

## Что внутри

| Файл | Что делает |
|---|---|
| `RKWhatsApp/Ext/ObjectModule.bsl` | Клиент API: HTTP, JSON, все методы платформы |
| `RKWhatsApp/Forms/НастройкаИнтеграции` | Адрес, ключ API, список номеров |
| `RKWhatsApp/Forms/НастройкаНомера` | Состояние номера и код для входа |
| `RKWhatsApp/Forms/Примеры` | Отправка, переписка, контакты |
| `RKWhatsApp/Templates/QR` | Страница с картинкой кода |
| `scripts/` | Сборка `.epf` и синтаксический контроль |
| `docs/` | Заметки: чем платформа отвечает и на чём спотыкается 1С |

Собранный `.epf` в репозитории **не хранится**: это двоичный слепок,
который не читается в diff и не сливается при расхождении. Собирайте его
из исходников (см. ниже).

## Настройка

1. В портале RK WhatsApp, раздел **«Доступ»**, выпустите ключ API.
2. Откройте `RKWhatsApp.epf` в 1С.
3. Введите адрес платформы (например, `https://rkwa.spherex.kz`) и ключ.
4. Нажмите **«Сохранить настройки»**, затем **«Проверить связь»** —
   появится список номеров.
5. Чтобы подключить номер: **«Добавить номер»** → откройте его →
   **«Запустить»** → через несколько секунд **«Показать код для входа»** →
   отсканируйте код в WhatsApp: *Настройки → Связанные устройства →
   Привязка устройства*.

Настройки хранятся в общем хранилище настроек 1С (`ХранилищеОбщихНастроек`,
ключ `RKWhatsApp` / `Подключение`) и общие для всей информационной базы.
Ключ вводится в режиме пароля и после сохранения на экране не показывается.

**Ключ API открывает все номера организации.** Он равносилен доступу ко
всей переписке: не пересылайте его письмом и не кладите в исходники.

## Какие адреса API используются

Аутентификация — заголовок `X-API-Key: <ключ>`. Для установок, где этот
заголовок ещё не поддержан, тот же ключ дублируется в `Authorization`
(без приставки `Bearer`); платформа принимает оба.

| Метод | Адрес | Где вызывается |
|---|---|---|
| `GET` | `/api/v2/instances` | «Проверить связь», «Обновить список» |
| `POST` | `/api/v2/instances` | «Добавить номер» |
| `GET` | `/api/v2/instances/:id` | «Обновить состояние» |
| `POST` | `/api/v2/instances/:id/start` | «Запустить» |
| `POST` | `/api/v2/instances/:id/stop` | «Остановить» |
| `GET` | `/api/v2/instances/:id/qr` | «Показать код для входа» |
| `POST` | `/api/v2/instances/:id/messages` | «Отправить текст», «Отправить файл» |
| `GET` | `/api/v2/instances/:id/chats` | «Обновить переписки» |
| `GET` | `/api/v2/chats/:id/messages` | «Показать сообщения» |
| `GET` | `/api/v2/instances/:id/contacts` | «Обновить контакты» |
| `POST` | `/api/v2/webhooks` | `ПодписатьсяНаСобытия` — из кода |

Полная спецификация — `docs/api/openapi.json` в репозитории платформы.

## Входящие сообщения приходят вебхуком

Опроса нет и не будет. Из внешней обработки фоновое задание не
запускается, а обработчик ожидания живёт ровно до закрытия формы: любой
опрос отсюда — это «работает, пока открыто окно».

Платформа сама шлёт `POST` на ваш адрес. Порядок такой:

1. Опубликуйте HTTP-сервис в своей конфигурации.
2. Один раз вызовите `ПодписатьсяНаСобытия` из модуля объекта обработки:

```bsl
Обработка = ВнешниеОбработки.Создать("RKWhatsApp.epf");
Настройки = Обработка.Настройки();
Соединение = Обработка.ОписаниеСоединения(Настройки.АдресПлатформы, Настройки.КлючAPI);

События = Новый Массив;
События.Добавить("message.received");

Ответ = Обработка.ПодписатьсяНаСобытия(Соединение,
	"https://ваш-сервер/hs/whatsapp/события", События, ИдНомера);
```

3. Сохраните `secret` из ответа: платформа подписывает им доставки, и
   второго экземпляра этого значения не будет.

## Отправка из своего кода

```bsl
Обработка = ВнешниеОбработки.Создать("RKWhatsApp.epf");
Настройки = Обработка.Настройки();
Соединение = Обработка.ОписаниеСоединения(Настройки.АдресПлатформы, Настройки.КлючAPI);

// Ключ повтора — идентификатор документа, из которого уходит сообщение.
// Тот же ключ означает то же сообщение: повторный вызов после разрыва
// связи не отправит человеку второе.
Ответ = Обработка.ОтправитьТекст(Соединение, ИдНомера, "+7 700 000 00 00",
	"Ваш заказ собран.", Строка(ДокументСсылка.УникальныйИдентификатор()));

Если НЕ Ответ.Успех Тогда
	ВызватьИсключение Ответ.Ошибка;
КонецЕсли;
```

Файл отправляется ссылкой, а не телом запроса: платформа скачивает его
сама, поэтому ссылка должна открываться и с её стороны.

```bsl
Ответ = Обработка.ОтправитьФайлПоСсылке(Соединение, ИдНомера, Получатель,
	"https://ваш-сервер/файлы/счёт-123.pdf", "Счёт 123.pdf",
	"Счёт на оплату", "document", КлючПовтора);
```

## Сборка

Собирается конфигуратором из XML-исходников — открывать `.epf` в
конфигураторе и править руками не нужно.

На машине с 1С:

```powershell
# 1. Разложить исходники в C:\Temp\rkwa\src (или задать свой каталог)
$env:RKWA_WORK = 'C:\Temp\rkwa'
$env:RKWA_1CV8 = 'C:\Program Files\1cv8\8.3.23.2236\bin\1cv8.exe'

# 2. Положить строку подключения в C:\Temp\rkwa\conn.txt, например:
#    /F"C:\Temp\rkwa\ib"                 — файловая база
#    /S"localhost\umc_dev2" /N"..." /P"..." — серверная

powershell -ExecutionPolicy Bypass -File scripts\build-epf.ps1
powershell -ExecutionPolicy Bypass -File scripts\check-modules.ps1
```

Результат — `C:\Temp\rkwa\RKWhatsApp.epf` и два отчёта:
`build-epf.txt`, `check-modules.txt`.

**Читайте отчёт, а не только код возврата.** Конфигуратор возвращает 0 и
собирает `.epf`, даже когда отбрасывает привязку события формы: скрипты
специально ищут в логе «не было обнаружено» и «ошибок не обнаружено».

Пустая файловая база для сборки заводится так:

```powershell
& "C:\Program Files\1cv8\8.3.23.2236\bin\1cv8.exe" CREATEINFOBASE File="C:\Temp\rkwa\ib"
```

Обработка не обращается ни к одному объекту конфигурации, поэтому
собирать и проверять её можно на пустой базе — рабочую трогать незачем.

Строка подключения лежит отдельным файлом намеренно: в ней пароль, а
аргументы командной строки видны в списке процессов всем, кто на машине.
